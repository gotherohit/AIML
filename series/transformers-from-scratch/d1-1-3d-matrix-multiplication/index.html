3-D matrix multiplication, finally visual

Inside every language model, the things being multiplied are 3-D blocks. Here's the one rule that tells you what comes out, shown in 3-D with the real GPT-2.

The rule[B, T, K] @ [K, N] = [B, T, N]. The last size of the left meets the first size of the right and disappears; everything in front comes along. Try every example in Colab (sections 1.0, 1.4, 1.11, 1.12).

The question

You know how to multiply two matrices: rows times columns. But inside a language model the things being multiplied are 3-D blocks, like [3, 4, 768]. What does block @ matrix mean, and what shape comes out? Here's the same question as PyTorch asks it. A [3, 4, 768] block times a [768, 64] matrix works. Flip the matrix and it fails:

RuntimeError: mm: mat1 and mat2 shapes cannot be multiplied (12x768 and 64x768)

My block was 3 by 4 by 768. So where did 12 come from?

Two dimensions, one picture

A is [2, 3], B is [3, 2]. One number of the answer = one row of A paired with one column of B: multiply the pairs, add them up. Row 0 of A is (1, 2, 0), column 0 of B is (2, 0, 1): 1×2 + 2×0 + 0×1 = 2. That's a dot product, the only operation in matrix multiplication. Doing it for every row and column gives C = [[2, 3], [3, 13]].

The row of A and the column of B both have 3 numbers, so they can pair up. That's the whole shape rule: [2, 3] @ [3, 2] → [2, 2]. The inner sizes meet and disappear, the outer sizes are what's left.

Add a dimension

Now X is [2, 3, 4]: two sheets, each an ordinary 3 × 4 matrix. Multiply by W [4, 2]: each sheet is multiplied by W on its own, the same W for both. Each sheet gives a 3 × 2 answer; stacked, that's [2, 3, 2]. The last size of X (4) meets the first size of W (4) and disappears, W's 2 goes on the end, and the 2 in front is just the number of sheets: it comes along.

Three ways, and where the 12 comes from

A loop over the sheets, flattening both sheets into one tall [6, 4] matrix, and plain X @ W all give exactly the same numbers. Flattening is closest to what the computer does, because every row is multiplied by the same W anyway.

That's the 12. PyTorch flattened my [3, 4, 768] block the same way: 3 sheets of 4 rows = 12 rows of 768. Then it tried to multiply them by a [64, 768] matrix: the 768 met a 64, nothing paired up, and the error showed the flattened shape.

Where blocks come from: text in GPT-2

So far the blocks were small made-up ones. In a language model they come straight from your text. Let's follow three real sentences through GPT-2: "The cat sat on", "My dog" and "Once upon a time".

First the text is cut into tokens, and every token has an ID number: its row number in GPT-2's vocabulary of 50,257 tokens. All sentences in a batch must be the same length, so the short one is padded with a filler token (GPT-2 uses its end-of-text token, ID 50256). The result is a flat table of IDs, 3 sentences by 4 tokens, [3, 4]. Two dimensions, no maths yet.

sentencetoken 0token 1token 2token 3
0The · 464cat · 3797sat · 3332on · 319
1My · 3666dog · 3290pad · 50256pad · 50256
2Once · 7454upon · 2402a · 257time · 640

GPT-2 looks each ID up

A number like 464 means nothing to the model by itself. GPT-2 keeps a big token table, wte, with one row of 768 numbers for every token it knows: [50257, 768]. The ID just says which row to copy. ID 464 ("The")? Copy row 464, which starts -0.069, -0.020, 0.064, -0.062 … and goes on for 768 numbers. In GPT-2's code this is literally a lookup: the table is an nn.Embedding, and wte(ids) copies one row per ID.

Do that for every ID and the flat table grows a third dimension. Each sentence becomes its own sheet, each token a row, and each row is 768 numbers wide: [3, 4] → [3, 4, 768]. That's the block from the first half of this page. It's the same picture as before: depth is the batch (sentences), rows are tokens, and the 768 numbers run sideways.

The same lookup, written as a matrix multiplication

Here's the nice part: that copying step can also be written as a matrix multiplication, and it follows exactly the rule from this page. Nothing about GPT-2 changes; it's a second way to describe the same step.

First, write every ID differently. Take ID 464 and make a row of 50,257 slots, one for every token GPT-2 knows. Put a 1 in slot 464 and a 0 everywhere else: 50,256 zeros and a single one. That's called a one-hot row.

Do that for every ID and the [3, 4] table becomes a block of one-hot rows: 3 sentences, 4 tokens, 50,257 slots each, [3, 4, 50257]. In PyTorch that's a single line, and it happens before any multiplication:

oh = F.one_hot(ids, num_classes=50257)   # [3, 4]  →  [3, 4, 50257]

Now multiply that block by the token table: [3, 4, 50257] @ [50257, 768]. Last meets first: the 50,257s meet and disappear, and out comes [3, 4, 768], the same shape the lookup gave.

Why are the numbers the same too? Look at one token. Stand its one-hot row next to the table, so every slot lines up with one row of the table. Each slot multiplies its whole row. The 50,256 slots that hold a 0 wipe their rows out. The single 1 sits next to row 464, so that row survives. Add everything up and what's left is exactly row 464: the same 768 numbers the lookup copied. Every other token does the same, each picking out its own row. On the real model, the multiplication and the lookup give identical blocks: the largest difference is 0.0.

So why does GPT-2 look up instead?

Cost. As a multiplication, every token takes 50,257 × 768 = 38,597,376 multiply-adds, and almost all of them are something times zero. The lookup gets the same answer by copying 768 numbers, about 50,000 times less work. Same answer, so the code takes the shortcut.

The multiplication view is still worth having in your head: it means the very first step of the model, from IDs to the block, is the same kind of operation as everything after it.

What comes after: weight matrices

From here on the model multiplies the block by weight matrices. Here's a real one from GPT-2's first layer, [768, 64] (the first 64 query columns of attention). [3, 4, 768] @ [768, 64]: the 768s meet, and out comes [3, 4, 64]. Every token of every sentence, multiplied by the same weights, in one go. The first numbers of the first token come out as -1.32, 2.97, 3.55, -3.27 ….

I ran this on the real model: the loop over sentences, the flatten and the plain @ all agree, to within 1.2 × 10⁻⁶ (rounding). (In the full model, position rows are added to the block and it's normalised before this multiplication. The shapes don't change, so the rule doesn't either.)

And now the error from the start reads itself. The last size of the block, 768, has to meet the first size of the matrix. Flip W to W.T and that first size is 64. They don't match, so PyTorch stops, and reports the block in its flattened form, 12x768.

When both sides are blocks

Sometimes both sides are blocks: [B, T, 64] @ [B, 64, T]. Then sheet 0 meets sheet 0, sheet 1 meets sheet 1, and the result is [B, T, T]. That's exactly how attention scores are computed (Episode 2). The front sizes are the batch dimensions: strictly, PyTorch needs them to be broadcastable, which means equal, 1, or missing on one side.

The whole rule

If a multiplication ever crashes, check those two sizes: the last of the left and the first of the right. For the full walk-through with every number, see the Episode 1 article.
